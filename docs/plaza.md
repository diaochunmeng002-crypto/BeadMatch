> 版本：**v0.1** ｜ 日期：2026-09-15

## 1. 要做什么

把 BeadMatch 做成一个**游戏广场**：一个程序里放多个给小孩玩的游戏，
按认知能力分类（`group` 分类 / `sort` 排序 / `space` 空间 / `plan` 规划 / `logic` 推理 / `memory` 记忆，
每类的核心能力和例子见 [../games/README.md](../games/README.md)）。

**串珠是其中第一个游戏**，属于「规划」类。它现在的东西（出题算法、题库、后端、前端、打包）
全部保留，只是位置和身份变了：从「整个项目」变成「广场里的一个游戏」。

## 2. 已定决策（2026-09-15）

| # | 问题 | 结论 | 连带影响 |
| --- | --- | --- | --- |
| 1 | 打包 | **保持现状，不重做**。打包是临时方案，只要求"搬家后还能打出现在的程序" | 搬完那次要改 `make_exe.bat` 的 3 处参数 + `launcher.py` 的 2 个默认路径（见 §7.1） |
| 2 | 题库放哪 | **每个游戏自己带**：`games/<game_id>/puzzles/` | 目录名仍叫 `puzzles/`，代码里的 `PUZZLE_DIR`、`BEADMATCH_PUZZLES` 都不改名，只改默认路径 |
| 3 | 进度 / 存档 | **不做**（不记玩过哪些题、不记成绩） | 广场层不需要任何存储模块，保持很薄。现状零改动——前端目前连 `localStorage` 都没用 |
| 4 | 项目总名 | **不改**，仓库 / exe / 图标继续叫 BeadMatch，内部用 `plaza/` 表示广场外壳 | 将来真要改名，一次性处理四处：GitHub remote、exe 名与图标、`make_exe.bat`、`%LOCALAPPDATA%\BeadMatch` |
| 5 | 跨游戏**格式**统一 | **不做元信息格式**，改为统一**骨架**（目录形状 + 代码接口） | 现有 300 个题目文件**一个字都不改** |

### 2.1 第 5 条为什么这么定

原本的设想是抽一个「元信息信封」（`game=` / `id=` / `level=` 等等），让所有游戏共用一套题目文件格式。
改成统一骨架，理由三条：

1. **只有一个游戏时，设计不出跨游戏的格式。** 记忆类、分类类游戏的题目长什么样，现在没人知道；
   凭空定的字段十有八九用不上。等第二个游戏真做出来，从两套**实际**格式里抽共同点，比现在猜准得多。
2. **广场真正依赖的不是文件格式，而是代码接口。** 广场要做的事只有：
   列出有哪些游戏、每个游戏有哪些等级、随机抽一道、按 id 取一道。
   这四件事调用游戏自己的函数就够了，广场**永远不直接读题目文件**。
3. **不用迁移数据。** 统一格式意味着 300 个文件都要插字段、重新提交；统一骨架一行数据都不用动。

代价：串珠这套 `created_at / created_by / solution_by / id / level / ...` 格式从
「项目标准」降级为**「串珠的私有格式」**。以后想做交换协议，再从多个游戏的实际格式里抽。

## 3. 目标目录结构

```
BeadMatch/
├─ run.py                     唯一入口：开发直接跑，打包也用它
├─ start/                     怎么跑、怎么发：打包脚本 / 桌面启动器 / 图标
├─ plaza/                     广场层（跟具体游戏无关）
│  ├─ server.py               FastAPI 主体：扫游戏、挂路由、托管静态
│  ├─ registry.py             扫 games/*/game.toml → 游戏清单
│  └─ web/                    广场首页 + 公共前端（语音 / 音效 / 键盘 / 主题）
├─ games/
│  ├─ beadmatch/              串珠（分类：规划）
│  │  ├─ game.toml            ← 还没有，第 2 步加：广场靠它发现这个游戏
│  │  ├─ core/                纯逻辑：走法算法 + 出题 + 题库读写/校验 + free_solver
│  │  ├─ api.py               后端（现在是整个 FastAPI app，第 2 步改成 router）
│  │  ├─ web/                 本游戏页面：棋盘渲染 + 朗读 + 规则
│  │  ├─ puzzles/<level>/<id>.txt
│  │  ├─ tools/               离线工具（批量出题）
│  │  └─ tests/
│  └─ group/ sort/ space/ plan/ logic/ memory/   按认知分类先建的占位 README（还没做）
└─ docs/
```

一句话概括分层：

> **`plaza/` 管「有哪些游戏、怎么开、声音怎么响、界面长什么样」；
> `games/<game_id>/` 管「这个游戏的规则、出题、题库、界面」。**

## 4. 游戏对广场的契约

广场只依赖下面四样，别的一概不管（尤其是**不管**题目文件里写了什么）。

### 4.1 `game.toml`

广场扫描 `games/*/game.toml` 得到游戏清单，用于首页展示。

```toml
id = "beadmatch"
name = "串珠"
category = "plan"        # group / sort / space / plan / logic / memory
summary = "把珠子按颜色归位"
```

### 4.2 `core/` 必须暴露的三个函数

广场通过它们拿题，不碰文件：

| 函数 | 作用 | 返回 |
| --- | --- | --- |
| `list_levels()` | 每个等级各有多少道题 | `{level: count}` |
| `pick(level)` | 从某等级随机抽一道 | 一条题目 |
| `load(id)` | 按 id 取一道 | 一条题目 |

**「一条题目」的统一形状**（只有这三样是广场关心的，`body` 里是什么由游戏自己定）：

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一标识 |
| `level` | 难度等级（整数） |
| `body` | 游戏自己的数据，广场原样透传给前端 |

### 4.3 `api.py`

导出 `router`（FastAPI），由广场挂到 `/api/games/<game_id>/` 下。
广场自己只提供通用接口：

| 接口 | 说明 |
| --- | --- |
| `GET /api/games` | 有哪些游戏（读 `game.toml`） |
| `GET /api/games/{game}/levels` | 该游戏每个等级各多少题（调 `list_levels`） |
| `GET /api/games/{game}/random?level=N` | 随机抽一道（调 `pick`） |
| `GET /api/games/{game}/puzzles/{id}` | 取一道（调 `load`） |

### 4.4 `web/`

游戏的页面与交互。广场给它一个容器，它自己渲染；公共能力（语音、音效、键盘、主题）
由广场提供，游戏只需要说明「这道题该怎么念」。

## 5. 分层与边界

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 广场层 `plaza/` | 发现游戏、列出题目、随机抽题、托管静态页面、公共前端能力、打包外壳 | 任何游戏规则、任何题目文件内容 |
| 游戏层 `games/<id>/` | 规则、出题算法、题库文件、校验、本游戏界面 | 端口、静态托管、打包方式 |

**校验也跟着分两层**（现在混在 `core/generator.py` / `api.py` / 测试里，第 2 步抽广场外壳时切开）：

| 层 | 校验什么 |
| --- | --- |
| 广场层 | 只有信封性质的东西：`id` 与文件名一致、`level` 能解析成整数 |
| 游戏层（串珠） | 行列数、空位必须在顶端、颜色集合、每色颗数、`level == ceil(moves / 10)`、`solution` 步数对得上且套回去真能解开 |

`level == ceil(moves / 10)` 属于串珠的私有规则（它是"乱走多少步"推导出来的），**不要提到广场层**。

## 6. 这一版明确不做

| 不做 | 原因 |
| --- | --- |
| 进度 / 存档 / 数据库 | 决策 3。广场因此不需要存储层 |
| 插件系统、动态加载、热插拔 | 几个游戏而已，`games/` 下加个文件夹 + 一行注册就够 |
| 改题目文件格式（加字段、改 JSON、改扩展名） | 决策 5。300 个文件一个字不动 |
| 现在就定「跨游戏交换协议」 | 等第二个游戏做出来，从实际格式里抽（`§2.1` 第 1 条） |
| 重做打包 | 决策 1。只要"还能打出现在的程序" |
| 前端上框架 / 上构建工具 | 现在是原生 JS 三件套，离线可跑；广场首页也不需要框架 |

## 7. 迁移步骤

**原则：一次只做一件事，每步做完都能跑、能测、能提交。**

### 7.1 第 1 步：纯搬家 + 真包化 ✅ 已完成（2026-09-15）

只搬文件、改导入，**逻辑一行不动**。

- 串珠相关的东西收进 `games/beadmatch/`（含 `puzzles/` 的 300 个文件）。
- **真包化**：现在全仓库有 10 处 `sys.path.insert(...)` + `import free_solver` 这种顶层模块导入
  （`generator.py`、`walk_gen.py`、`server/app.py`、4 个测试文件、`make_puzzles.py`、`make_exe.bat`）。
  一个游戏时只是丑；两个游戏时同名顶层模块会互相覆盖，且报错难查。
  已改成真包导入（`from games.beadmatch.core.free_solver import ...`），各层加了 `__init__.py`。
- 打包跟着改了这些地方（否则"还能打出现在的程序"不成立）：

  | 文件 | 改前 | 改后 |
  | --- | --- | --- |
  | `make_exe.bat` | `--add-data "web;web"` | `--add-data "games\beadmatch\web;games/beadmatch/web"` |
  | `make_exe.bat` | `--add-data "puzzles;puzzles"` | `--add-data "games\beadmatch\puzzles;games/beadmatch/puzzles"` |
  | `make_exe.bat` | `--paths "solver"` + `--hidden-import free_solver` | **两行都删掉**（真包导入后 PyInstaller 自己找得到） |
  | `launcher.py` | `import server.app as app_module` | `import games.beadmatch.api as app_module` |
  | `launcher.py` | 数据目录 `<exe旁>/puzzles` | `<exe旁>/games/beadmatch/puzzles`（`BEADMATCH_WEB` 同理指向资源里的 `games/beadmatch/web`） |

**验收结果**：58 项测试全过；`make_exe.bat` 打出的 exe 起得来（`/api/health`、`/api/levels` 报 300、
首页和 `/static/app.js` 都是 200，题库自动拷到 exe 旁边的 `games\beadmatch\puzzles`）。

**入口变了**：`python -m server.app` → **`python run.py`**（`--host` / `--port` / `--reload` 三个参数照旧）；
打包仍是 `make_exe.bat`。命令都写进 [how_to_start.md](how_to_start.md) 了。

### 7.2 第 2 步：抽广场外壳

写 `plaza/registry.py`（扫 `game.toml`）+ 广场首页 + 把公共前端（语音 / 音效 / 键盘 / 主题）
从 `web/` 提到 `plaza/web/`。串珠变成「广场里的第一个游戏」，**功能不变**。

**验收**：打开首页能看到「串珠」并点进去；串珠的行为跟搬家前完全一样。

### 7.3 第 3 步：写第二个游戏

**这一步才是真正的验收**：只有一个游戏时设计出来的抽象，十有八九是错的。
建议挑跟串珠差异最大的那一类（比如记忆类：看/听一段序列再复述），
因为它对「题怎么存、界面怎么渲染、声音怎么用」的假设跟串珠完全不同
—— 只有这样才试得出 `game.toml` 和 `plaza/` 的接口够不够用。
