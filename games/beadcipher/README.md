# beadcipher · 彩珠密令

两个人用一套实体珠子玩：一个人藏一排，另一个人猜。程序只显示题卡，
不保存密令，不记录猜测，也不自动判定。

现在共有 **7 个难度、21 道精选题卡**。页面只有三个操作：
选择难度、查看题目、换一题。

## 一批题卡怎么玩

1. 一个人按题目给出的珠子摆一排并盖住，记住密令。
2. 另一个人用同样的珠子摆出自己的猜测。
3. 提供线索的人按题卡上的线索约定回答。
4. 没有猜测次数上限，猜中后交换，再换一题继续。

程序不提供最终答案；需要揭晓时直接把实体密令打开。

## 5 个难度

| 难度 | 题数 | 线索语言 | 珠子 / 可能密令 |
| --- | --- | --- | --- |
| 1 | 4 | 直接标出正确位置 | 2～4 颗，2～6 种 |
| 2 | 2 | 第一处错误 | 3～4 颗，6～24 种 |
| 3 | 3 | 最长连续正确 | 4～5 颗，12～120 种 |
| 4 | 4 | 只报位置正确数 | 3～6 颗，6～360 种 |
| 5 | 4 | 高级线索 | 4～6 颗，24～720 种 |
| 6 | 2 | 六色严格反馈 | 6 颗，360～720 种 |
| 7 | 2 | 延迟 / 受限反馈 | 6 颗，360～720 种 |

题数刻意不追求整齐：L1 用 4 道热身，L2 两道桥接，L3/L4/L5 逐步加入更多珠子和颜色，
L6/L7 只在六色、大搜索空间下加入更严格的线索条件。
珠子数量只是表现，实际难度还要看同色结构造成的可能密令数量 —— 例如三颗双红一蓝
只有 3 种密令，四颗两红两蓝也只有 6 种。

## 题卡文件

题库位置：`puzzles/<等级>/<id>.txt`。

```text
# colors: Yellow Green Red Purple Blue Orange

created_at=2026-10-22 23:35:00
created_by=manual
id=20261022-233500-bc01
level=1
title=三色密令
beads=RBY
kind=positions
clue_rule=每次只告诉位置对了几颗，不说是哪几个位置。
```

主要字段：

- `beads`：这一局实际使用的珠子；`RRBY` 表示两颗红、一颗蓝、一颗黄；
- `kind`：这道题所属的线索语言；
- `clue_rule`：双方本局遵守的完整线索约定；
- 文件里没有答案，密令由现场每局重新摆。

检查题库：

```powershell
python -m games.beadcipher.core.cards --list
```

## 单独运行

```powershell
python -m games.beadcipher.api
```

打开 <http://127.0.0.1:8060>。从游戏广场进入时使用：

<http://127.0.0.1:8000/games/beadcipher/>

## 难度原则

- 难度主要来自线索能提供多少信息，不靠颜色换皮；
- 一级只使用一种线索语言；
- 同级题改变材料结构或线索方式，并使用颜色无关的结构签名去重；
- 全部题卡可以反复玩，因为密令不是预先写死的。
