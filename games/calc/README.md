# calc

**计算**（核心能力：数感与计算）—— 用串珠数一数、比多少、做加减、分一分。

Count them, compare them, add and take away.
How many, which is more, how many left.

> **这一份是玩法 + 难度设计 + 接口**（2026-09-16）。现在的进度：卡片格式、**L1~L12 的 120 张卡**、
> **后端和前端都能跑了**（`core/` + `api.py` + `web/`）。
> 大体规矩见 [../README.md](../README.md)。

## 1. 一道题长什么样

**一堆珠子（哪些颜色、各几颗）+ 一句话要求 + 要回答的那个数。**
孩子用手上的实物珠子数、摆、拿，把答案说出来（或者在屏幕上摆出来）。

例：`🔴 3 颗 🔵 4 颗` ＋「红的多还是蓝的多？」→ **蓝的多，多 1 颗**。

## 2. 难度阶梯 L1~L12

主线：**数感 → 加减 → 分解 → 穷举 → 组合/约束 → 多步综合**。
一档只加一根轴（玩法 **或** 数的范围），别同时动两根。

| 级 | 玩法 | 核心能力 | 数的范围 |
| --- | --- | --- | --- |
| L1 | 数一数（有几颗） | 点数 | 5 以内 |
| L2 | 一样多（一一对应） | 配对 | 5 以内 |
| L3 | 比多少（哪边多 / 少） | 比较 | 5 以内 |
| L4 | 合起来（两组数量合并） | 加法 | 5 以内 |
| L5 | 拿走（拿走后剩多少） | 减法 | 5 以内 |
| L6 | 补数（还差几颗，实物一颗一颗添） | 差 | 10 以内 |
| L7 | 拆成两组 | 分解 | 10 以内 |
| L8 | 缺数（2 + ? = 6） | 符号化的差 | 10 以内 |
| L9 | 连加连减（+2 再 −1）+ 三组以上 | 连续、多组 | 10 以内 |
| L10 | 拆法找全（不重不漏） | 穷举 | 10 以内 |
| L11 | 凑数（用颜色组合出指定数量）+ 限制条件 | 组合 + 约束 | 10 以内 |
| L12 | 带条件的全部凑法 + 综合 | 穷举 + 多步 | 20 以内 |

### 每级现在长什么样（各 10 张，共 120 张）

| 级 | 玩法 | 问法举例 | 答案 |
| --- | --- | --- | --- |
| L1 | 数一数 | 数一数：停车场上停了几辆小汽车？ | 4 |
| L2 | 一样多 | 把黄色小鸭子和红色小鸭子一只一只地配。配完之后，多出来的有几只？ | 1 |
| L3 | 比多少 | 红色气球有 3 个，黄色气球有 2 个。哪种颜色的气球多？ | 红色 |
| L4 | 合起来 | 黄色小汽车 2 辆和红色小汽车 2 辆停在一起，一共几辆？ | 4 |
| L5 | 拿走 | 盒子里一共有 5 颗小草莓，把红色的 3 颗拿走，还剩几颗？ | 2 |
| L6 | 补数（实物） | 盘子里有 4 块小饼干，再添几块就到 6 块了？ | 2 |
| L7 | 拆成两组 | 把 6 块小饼干分成两盘：一盘 2 块，另一盘几块？ | 4 |
| L8 | 缺数（符号） | 不用摆珠子，直接算：2 块再加几块，正好是 6 块？ | 4 |
| L9 | 连续变化 / 三组 | 停车场原来有 4 辆小汽车，先开来 2 辆，再开走 1 辆，现在还剩几辆？ | 5 |
| L10 | 拆法找全 | 把 5 块小饼干分成两堆，每堆至少 1 块，不管哪堆在前，一共有几种分法？ | 2 |
| L11 | 凑数 | 用黄色小饼干和红色小饼干凑出 5 块，一共有几种凑法？ | 2 |
| L12 | 带条件的全部凑法 | 用黄色、红色、蓝色 三种小饼干凑出 5 块，每种颜色至少 1 块，一共有几种凑法？ | 6 |

出题时守的几条：**珠子数"够用就行"**（题里最大的数 + 一点余量，最多 10 颗）；
同一级里颜色搭配不重复；十张加起来**各颜色用掉的颗数拉平**（全库 97~124 之间）；
答案一律**按材料算出来**，不是手写的。

## 3. 卡片长什么样（草案）

照 `logic` 的格式来（**注释区 + 元信息区 + 正文区**），一卡一文件，放 `puzzles/<等级>/<id>.txt`。
不同的是：**珠子带数量**（同一颗颜色写几遍就是几颗），而且**答案多半是一个数**。

```
# colors: Yellow Green Red Purple Blue Orange

created_at=2026-09-16 10:15:00
created_by=manual
id=20260916-101500-a3f1
title=停车场 🚗
level=1
task=count
participants=R R B B
answer=4

数一数：停车场上停了几辆小汽车？
```

| 字段 | 例子 | 说明 |
| --- | --- | --- |
| `id` / `title` / `level` | `20260916-101500-a3f1` / `停车场 🚗` / `1` | 文件名就是 id（**日期-时间-4 位**，跟串珠 / logic 一个叫法）；`title` 是这张卡的名字 |
| `task` | `count` | 玩法记号：`count` 数一数 / `compare` 比多少 / `equal` 一样多 / `add` 加法 / `subtract` 减法 / `group` 分组 / `make` 凑数 / `missing` 缺数 |
| `participants` | `R R B B` | **参与者**：这道题用到的珠子。写法跟记忆那套一样（`R` / `红` / `🔴` 都认），重复几次就是几颗 |
| `answer` | `4` | **答案**：一般是个数；比较题写成哪边多（`R` / `B` / `equal`） |
| 正文 | `数一数：停车场上停了几辆小汽车？` | **规则**：一字不改，就是给孩子听的那句话 |

现在 **L1~L12 每级 10 张，共 120 张**（`puzzles/<等级>/`）。L1 那十张：6 张问「一共有几颗」、
4 张问「某色有几颗」；珠子 3~5 颗（L1 的口径是 5 以内）、2~5 种颜色。

## 4. 接口

```bash
python -m games.calc.api            # 默认 127.0.0.1:8030
```

打开 <http://127.0.0.1:8030/docs> 可以点着试（前端还没做，根路径现在是一张说明页）。
跟 `logic` / `memory` 同构，前缀 `/api/calc`，端口 **8030**（8000 串珠、8010 推理、8020 记忆）。

| 接口 | 返回什么 |
| --- | --- |
| `GET /api/calc/health` | 活着没 + 题库目录 |
| `GET /api/calc/levels` | 每个等级各多少张卡 |
| `GET /api/calc/puzzles?level=1` | 列出卡片（只读文件头，比较快） |
| `GET /api/calc/puzzles/{id}` | 取一张卡：参与者 + 玩法 + 规则 + 答案 |
| `GET /api/calc/random?level=1` | **「出题」**：随机抽一张（多带一个 `pool_size`） |
| `POST /api/calc/check` | **判一个答案**：`{"id": "20260916-101500-a3f1", "answer": "四"}` |

取一张卡返回的样子（`participants` 里**多的颜色排前面**）：

```json
{
  "id": "20260916-101500-a3f1",
  "title": "两红两蓝",
  "level": 1,
  "task": "count",
  "task_cn": "数一数",
  "participants": [{"color": "R", "name": "红色", "cn": "红", "en": "Red", "emoji": "🔴", "count": 2},
                   {"color": "B", "name": "蓝色", "cn": "蓝", "en": "Blue", "emoji": "🔵", "count": 2}],
  "beads": 4,
  "colors": 2,
  "rule": "数一数：一共有几颗珠子？",
  "answer": "4",
  "answer_value": 4,
  "created_at": "2026-09-16 10:15:00",
  "created_by": "manual"
}
```

`answer` 是原样给人看的，`answer_value` 是规范化之后的（数字 / 颜色字母 / `"equal"`）。

**跟记忆不一样的地方：这儿有 `/check`。** 计算题的答案是一个数（或者哪边多），
孩子说完就能判 —— 答案写 `5`、`"五"`、`"蓝"`、`"equal"` 都收（中文数字认到二十）。
判定不用像记忆那样全靠人。`/check` 返回 `{ok, given, expected, expected_answer, task}`，
对错都返回 200，用 `ok` 区分（跟 `logic` 一个路子）。

## 5. 页面

起后端就有（`python -m games.calc.api` → <http://127.0.0.1:8030>）。
版式跟记忆一套（原生 JS 三件套，不用构建、不用框架）：**材料 / 题目** 两块，就这些。

| 块 | 里面是什么 |
| --- | --- |
| **材料** | 珠子 + 颜色名 + `几颗`（`蓝色 3 颗`）—— 大人照着这个准备，跟「读一遍」念的同一个说法 |
| **题目** | 卡里那句规则，原样显示；底下按「看答案」才露出来一行答案 |

一局：大人按材料摆珠子 → 「读一遍」（把材料和规则念给孩子听）→ 孩子说答案 →
大人按「看答案」自己对一眼 → 「换一题」。**页面上不判对错**，判定是人做的
（跟记忆一个路子：软件只负责出题）。

右上角三个按钮：「读一遍」、「看答案」、「换一题」。键盘：`空格` = 换一题、`R` = 读一遍、
`A` = 看答案。答案显示成人话：卡里写 `5` 就显示 `5`，写 `B` 显示「蓝色」，写 `equal` 显示「一样多」。

> 后端其实还有一个 `POST /api/calc/check`（交一个答案自动判对错，见 §4），**页面没用它** ——
> 哪天想让孩子在屏幕上答题，接回来就行。

## 6. 几条约定

**珠子数"够用就行"。** 一题用几颗珠子，由题里最大的那个数决定（加一点余量），
不是"级别越高桌上越多"—— 二十颗珠子摊在桌上，对 6 岁孩子是干扰，不是难度。
难度靠**数的范围**（5 → 10 → 20）和**操作步数**。

**颜色是这套珠子独有的那根轴。** 从 L4 加法起就用两种颜色各一堆，到 L11 变成真正的
约束（"两种颜色都要用""红色比黄色多 2 颗"）。用颜色出计算题，纸质练习册做不了 ——
这才是拿串珠算数的理由。

**题目都能判。** 计算题的答案算得出来，多解题的解集能穷举 —— 所以这个游戏跟 `logic`
一样可以自动判定，还能照它那样加一条"检查题库：这题解有几个"。判定不用像记忆那样靠人。

**级别的分界**（以后要调就调这几条）：

- L1~L3 只练"数、配、比"，不出算式；
- L6 的补数是**实物版**（一颗一颗添到够），L9 的缺数是**符号版**（不摆出来直接算）——
  同一件事的两级，别当成两个新玩法；
- L10 只管"找全、不重不漏"，**L12 才加条件** —— 这是两级，不是一回事；
- L11 把"凑数"和"限制条件"合在一起（原来是两级，其实是一件事）。
