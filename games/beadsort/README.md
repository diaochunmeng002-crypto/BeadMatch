# beadsort —— 竞技串珠

**竞技串珠**（核心能力：多步规划）—— 一次只能把**最顶上那颗**放到**空柱**或**同色柱顶**上，
把每种颜色收齐到一根柱子就算赢。

One ball at a time, and it may only land on its own colour or an empty peg.

> 跟 [../beadmatch/](../beadmatch/)（宝宝串珠）是**同一个玩具、两种玩法**：
> 宝宝串珠"落点只要有空位就能放"（松、永远有解）；竞技串珠"只能同色或空柱"
> （紧、**会走进死局**）。代码是从那边复制过来改的，**两套题库互不通用**
> —— 那 300 道旧题在新规则下全不合法，已经清掉重出。

## 1. 规则

- 一次拿某根柱子**最顶上的一颗**珠子；
- 目标柱子**要么空着、要么顶色跟这颗一样**；
- 赢：**每种颜色全部集中在一根柱子**上，其余柱子空着。

⚠️ **会有死局**：走错一步可能就回不去（宝宝串珠不存在这种情况，那边"60 颗 < 70 格"怎么都解得开）。
所以玩的时候要"先想再动"；卡住了就照题面重新摆过。

## 2. 玩

```bash
python run.py        # 广场首页第 2 张卡片（/games/beadsort/）；也可以单独跑 python -m games.beadsort.api
```

页面跟宝宝串珠同一个手感：把局面画成一根根柱子、**点柱子把颜色从下往上读出来**（带语音）、
「演示解法」一步步把球飞过去（带落珠声）。页面上写着这条规则。

## 3. 出题：施工式反走

一句话：**把一条合法解"倒着演一遍"，出来的就是题。**

1. 从**已解局面**（每种颜色占满一根柱子）出发；
2. 每一步：挑一根**拎起来还露着同色**的柱子（顶上那颗拿走后露出的还是同色，或者它就拿空了），
   把它顶上那颗放到**任意还有空位**的柱子上 —— **放哪儿不限颜色，混色就是这么来的**；
3. 走够步数 → 得到题面；**把施工步骤倒过来**就是给玩家的解（第 2 条正好保证解里每一步都合法）。

为什么不沿用宝宝串珠那套（"合法乱走 + 反走即解"）：

- **合法走法打不乱局面** —— 只能摞同色，意味着你永远没法把两种颜色混进一根柱子，
  从已解局面合法乱走，出来的"题"每根柱子还是单色（只是柱子换了个位置），是假题；
- **随机撒又基本无解** —— 小棋盘（5 柱 / 3 色 / 空 2 根）用完整 BFS 实测 0/20 有解，
  跟当年旧规则下"6 色 7 柱随机局面 0/30"是同一个现象。

施工式反走的好处：**不依赖求解器、秒级、起点一定有解**。

```bash
python -m games.beadsort.tools.make_puzzles --series 10 --count 20   # 出 20 道 1 级（走 10 步）
python -m games.beadsort.core.generator --steps 40 --seed 7          # 单出一道（40 步）
python -m games.beadsort.core.generator --show <题目文件>             # 读一道并校验
```

**校验**：读题目文件时会**逐步**验合法性（每一步都得符合竞技规则）+ 走完必须收齐，
不合规的题直接读不进来。

## 4. 采样器：先量一量天花板

出题器是"走满 N 步"。但实验发现 **走得更久 ≠ 出得更乱**：20 步和 120 步最后都落在
同一个乱度附近，多出来的步数基本是原地打转（60 颗珠子里，离位的十几到二十几颗就到头了）。

所以抽样换一套玩法 —— **不追求步数，让随机过程玩命走，走不动或停滞就停，按最终局面的乱度分档**：

| | 出题器 `tools/make_puzzles.py` | 采样器 `tools/sampler.py` |
| --- | --- | --- |
| 走法 | 两步前瞻的贪心（专挑最能打散的） | **纯随机** |
| 目标 | 走满 N 步，走不满就换种子 | **走不动 / 到上限 / 停滞就停** |
| 防打转 | 不走重复局面 | 禁立即反向 + 禁重复局面 + 停滞截断 |
| 产出 | 一条题 | 一大批题 + **乱度分布** |

放心的地方：每一步都是合法逆操作 → **最终局面一定有解**（把路倒过来就是解），
所以采样器不依赖求解器，也永远采不出不可解的题。

```bash
python -m games.beadsort.tools.sampler survey --n 10000                   # 跑 1 万道，看离位分布
python -m games.beadsort.tools.sampler survey --scales 1000 10000 50000   # 看天花板会不会随样本量涨
python -m games.beadsort.tools.sampler survey --n 2000 --repeat allow     # 对照：不加防打转的老做法
python -m games.beadsort.tools.sampler survey --n 3000 --csv out.csv --top 5   # 逐题明细 + 最乱的前 5 道
python -m games.beadsort.tools.sampler dump --min-misplaced 20 --count 5       # 把最乱的另存成题目
python -m games.beadsort.tools.sampler build --n 10000 --per-level 20 --clear  # 跑 1 万道，按步数重建题库
```

报表里看三样：

* **离位** `misplaced` —— 不在"自己家"的珠子数，同时是解的**下界**（60 颗里到底有几颗非搬不可）；
* **色段** `segments` —— 颜色被打散的程度（上限 = 珠子数）；
* **收工原因** `dead-end / stagnation / cap` —— 是走不动了，还是被我们截断了。

跑 1 千 / 1 万 / 5 万看**最高离位会不会继续涨**：不涨就说明那是规则本身的结构上限，
不是采样不够。（`dump` 默认写到 `puzzles_candidates/`，**不是**正式题库。）

对照实验（同样 7 柱 6 色）：老做法（`--repeat allow`，不截断）平均要硬走 **374 步**，
离位平均 12.6、最高 22；新做法平均只走 **21 步**，离位平均 11.9、最高 27 —— 
**多走的 350 步完全没换来更乱的题。**

## 5. 难度

- 等级 = 解的长度 ÷ 10 向上取整（跟宝宝串珠同一个口径），**L1 = 10 步**，每级 20 道；
- ⚠️ **"步数"不等于"最少步数"**：施工式反走出来的解里有"来回蹭"，最短解通常更短；
  而且竞技规则下求最优是 **NP-完全**（见 [../../docs/solver_research.md](../../docs/solver_research.md)），
  所以只标"步数"，永远别标"最少步数"；
- 但那套口径有个硬伤：**步数走不上去**（走满 200 步的题，解里全是废步）。
  采样器给的出路是**按最终局面的乱度分档**，`misplaced / segments` 已经写进题目文件里备查；
- 现在这套题库是采样器建的：**跑 10 万道，按解的长度分档，每档最多 20 道** →
  1~5 级各 20 道，一共 100 道。重建：`sampler build --n 100000 --per-level 20 --clear`。
- ⚠️ 默认 `--pick first` 是**先到先得**（按种子顺序取每档最早的那 20 道），所以
  "1 万道"和"10 万道"跑出来的 1~4 级是**同一批题** —— 多加的样本只对**稀少的档**有用
  （5 级要 41 步以上，1 万道里只有 1 道，10 万道才凑满 20 道）。
  想让 1~4 级也换一批，就换 `--seed0`，或者用 `--pick chaos`（取每档最乱的那 20 道）。
- 速度：1 万道十几秒到半分钟、10 万道 5 分钟上下（看机器忙不忙，单条约 1~3 毫秒）。
- 离位跟着难度涨（1 级平均 7.5 → 4 级 17.9），所以两个口径基本自洽 —— 这是巧合般的好消息，
  不是必然（见上一节的天花板）。

## 6. 接口

跟其它游戏完全同构（广场里挂在 `/api/games/beadsort/...`，单独跑在 `http://127.0.0.1:8000`）：

| 接口 | 作用 |
| --- | --- |
| `GET /health` · `/levels` · `/puzzles?level=1` · `/puzzles/{id}` · `/random?level=1` | 题库浏览 / 抽题 |
| `POST /next` | 提示下一步（拿局面问，返回一步走法） |
| `POST /play` | 算出/读出整条解（「演示解法」用） |
| `POST /generate` | 现出一题（可以存进题库） |

## 7. 现状与待定

**已经好的**：规则、出题（施工式反走）、逐步合法性校验、**采样器（乱度分布 / 导候选）**、
**100 道题（1~5 级，每级 20 道）**、页面上的规则说明、**73 项测试全过**。

| 待定 | 备注 |
| --- | --- |
| **空柱数** | 现在是 6 色 7 柱 = **只有 1 根空柱**（经典配置里最紧的一种）。嫌窄就改 5 色（2 空柱），生成器一行参数 |
| **难度口径** | 我们一步一颗；手机上那些"一次倒一摞"的版本，同样"10 步"的手感差很多 —— 要不要另定一套 |
| **乱度 → 等级** | 采样器把 `misplaced / segments` 记进题目里了，但**等级还是按步数算的**。要不要改成按乱度分档，得先看 5 万道那份分布 |
| **"退一步 / 重来"** | 死局不可避免，孩子卡住时得有路可退（回到题面重摆） |
| **打包** | `start/make_exe.bat` 还没带这个游戏（要打五合一才需要改） |
