# games —— 游戏都放这儿

一个游戏一个文件夹，文件夹名 = **游戏 id**（小写英文，比如 `beadmatch`）。每个游戏自带：
`core/`（纯逻辑）、`api.py`（后端接口）、`web/`（页面）、`puzzles/`（题库）、`tests/`。

- 广场靠 **`game.toml`** 发现游戏：没有这个文件的文件夹**对广场是隐形的**（不会被列到首页）。
- 现在四个游戏都有 `game.toml` 了 —— `python run.py` 起的就是**广场**（首页 `/` 列出所有游戏，
  每个游戏在 `/games/<名字>/`，接口在 `/api/games/<名字>/...`，见 [../docs/plaza.md](../docs/plaza.md)）。
- **已经有游戏的**：`beadmatch`（规划）、`logic`（推理）、`memory`（记忆）—— 每个都是
  `core/ + api.py + web/ + puzzles/ + README` 一整套；`calc`（计算）开了个头
  （卡片格式 + L1~L12 共 120 张题 + 后端 + 前端）；`pattern`（找规律）还是占位 ——
  只有一个 README（写着这类游戏是什么）。
- **分类不靠文件夹记**：`category` 写在每个游戏自己的 `game.toml` 里，所以不需要
  `plan/` `sort/` `space/` 这种空文件夹占位（2026-09-16 都删了）。
- **`group`（分类）这一类整个不做**，理由见下面那张表后面那段。
- **题目文件怎么命名**：`puzzles/<等级>/<id>.txt`，`id` 用 **`<日期>-<时间>-<4 位>`**
  （例如 `20260916-101500-a3f1`），而且 `id` 必须跟文件名一致（各游戏的检查命令会验这一条）。
  串珠、logic、calc 都是这么叫的；`memory` 那 100 张是早期起的 `1-01` 这种名字，还没改。
- 真做某个游戏时，建 `games/<游戏英文名>/`，把分类写进它的 `game.toml`（例如 `category = "memory"`）。
- 广场的整体规划见 [../docs/plaza.md](../docs/plaza.md)。

## 五大类（按认知能力）

| 文件夹 | 分类 | 核心能力 | 例子 |
| --- | --- | --- | --- |
| `beadmatch` | 规划 | 多步思考 | 串珠对对碰（就是这个游戏） |
| `logic` | 推理 | 条件约束 | "小红在小绿前面" |
| `memory` | 记忆 | 工作记忆 | 看几秒后盖住、凭记忆把排列摆回来 |
| `pattern` | 找规律 | 发现规律 | 颜色按什么在变、下一颗是什么 |
| `calc` | 计算 | 数感与计算 | 数一数、比多少、合起来、拿走、分一分 |

> **`plan` / `sort` / `space` 三个占位文件夹删了**（2026-09-16）：分类写在 `game.toml` 的
> `category` 里，不用拿空文件夹占位。`plan`（规划）本来就只有 `beadmatch` 一个游戏
> （游戏自己的文件夹就是它）；`sort`（排序）那个位置由新的 `pattern`（找规律）接上；
> `space`（空间）暂时没打算做。

> **为什么把「分类」删了**：这套珠子只有**颜色**一种属性（6 色，同尺寸同形状），
> 所以"把有共同点的放一起"能出的题只剩一个形状 —— 把颜色分成几组。这样一来
> L1~L6 其实是同一件事（每组一种颜色），难度长不起来。占位 README 里举的
> 「一样大的、都是圆的」这套珠子压根分不出来（全都是）。
>
> - 真要考"发现共同属性"，得先有**第二条属性轴**（比如再添一套不同尺寸的珠子）——
>   那时候分类立刻变成二维：红的大珠子一堆、红的小珠子一堆……
> - 另一个折中方向是把它做成**分堆**（平均分 / 分成一模一样的小组 / 分不掉的找出为什么），
>   用现有珠子就能玩、程序也能判定 —— 但那本质是"数量"，不算"分类"，要做就另起一个文件夹。
