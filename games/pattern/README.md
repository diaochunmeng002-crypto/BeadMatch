# pattern —— 找规律

**看出一串珠子在按什么变，然后接着往下摆。**（核心能力：发现规律）

跟前面四个游戏最大的不同：**这个游戏不让孩子在屏幕上摆珠子**。屏幕只做三件事 ——
出题、在必要时念出来、点「看答案」之后亮出标准答案和规律解释；动手的是**实物珠子**。
所以它没有 `POST /check`，也没有拖动：判定是孩子/家长自己看一眼（跟 `memory` 一样）。

```bash
python run.py                       # 广场首页第 6 张卡片（/games/pattern/）
python -m games.pattern.api         # 单跑这个游戏（8040）
python -m games.pattern.core.cards  # 检查题库（唯一解、颜色上限、题面/答案对不对）
python -m games.pattern.tools.make_puzzles   # 批量出题（每档补到 20 道，写完自动逐题校验）
```

## 玩（前端）

页面长这样：**题目名** → **题面**（珠子按规律排好，空位是虚线圈，标着序号；
分组题是一组一个框，框下写着「第 N 组」）→ **任务说明** → 三个按钮。

| 操作 | 效果 |
| --- | --- |
| 点珠子 | 读它的颜色名（"红色"） |
| 「读一遍」/ `空格` | 把题目名、题面、任务说明念一遍（揭晓后连答案和规律一起念） |
| 「看答案」/ `回车` | 亮出**标准答案**和**规律解释**（空位填上答案、放错的那颗圈出来） |
| 「摆对了」/ `y` | 通关（"叮"一声） |
| 「没对，再来一次」/ `n` | 答案收回去，题面留着，重新摆 |
| 「换一题」 | 同一档里再抽一道（现在这道会被剔掉，不会原地打转） |
| `←` `→` | 上一档 / 下一档 |

难度就是 `puzzles/1..10` 十档，**每档 20 道（一共 200 道）**。家长按孩子的情况挑挡，
同一档里用「换一题」换着做；`←` `→` 可以一档一档挪。

## 难度阶梯（L1~L10 各新加一个想法）

| 级 | 新加的那一个想法 | 题面（`?` 是空位） | 任务 / 答案 | 练什么 |
| --- | --- | --- | --- | --- |
| L1 | 重复单元（2~4 颗，颜色都不重复） | `R B R B R ?` / `R B G R B ?` | 补下一颗 | 看出"一段一段重复" |
| L2 | 单元里有**重复色**（AAB / ABB / AAAB / ABBB / AABB） | `RRB RRB RR ? ? ?` | 接下 3 颗 | 长单元 + 相同颜色 |
| L3 | 同一循环，反过来问"缺的是哪一颗"（单元 2~4 颗） | `RBG R ? G RBG` | 补中间那颗 | 两边对着看、定位 |
| L4 | 一组比一组**多**（起点 1~4、步长 1~2） | `R / BB / RRR / ?` | 摆下一组 | 数量 + 颜色一起看 |
| L5 | 一组比一组**少**（步长 1~2） | `R×5 / B×4 / R×3 / ? / ?` | 再摆后面两群 | 别只会"加一" |
| L6 | 每组多取**几种新颜色**（起点/步长/取到第几组都可变） | `R / RB / RBG / RBGP / ?` | 摆下一组 | 数量 + 颜色顺序 |
| L7 | 找错并**修正**一颗（单元 2~4 颗，错的位置随机） | `RRB RRB R?B` | 说出第几颗、该是什么颜色 | 验证规律、纠错 |
| L8 | 每群是上一群的 **2 倍或 3 倍** | `R / BB / RRRR / ?` | 摆下一组 | 倍增（再翻就超过手上的珠子了） |
| L9 | 走到头**往回走**（镜像单元，2~6 颗来回） | `RBGGBR RB ?` | 下一颗 | 对称，不是更长的重复 |
| L10 | 复合：先补错漏、再往下摆（3~5 组） | `R / BB / RR / ?` | ① 补一颗；② 摆下一群 | 两个动作连做 |

**同一档 20 道题是 20 个不同形状**（形状签名不含颜色：单元长度/组成、给了几颗、空位在哪、
组数怎么变、镜像几颗……见 `core/cards.py` 的 `shape_key`）—— 不是一道题换个颜色说 20 遍。

设计规矩（写新题时照着来）：**一级只新加一个想法**；答案必须唯一、能当场验证；
题面 + 答案加起来不能超过手上的珠子（每种颜色 10 颗）。

## 题目文件

`puzzles/<等级>/<id>.txt`，`id` 用 `<日期>-<时间>-<4位>`（例：`20261017-100101-1a01`，
必须跟文件名一致）。格式跟另外几个游戏同构（注释区 + 元信息区）：

```
# colors: Yellow Green Red Purple Blue Orange

created_at=2026-10-17 10:01:01
created_by=manual          # 手写的题；历史页「出题者」那栏会显示 manual
id=20261017-100101-1a01
level=1
title=红蓝排队
story=假装这些是小汽车：红、蓝、红、蓝、红，一辆接一辆开过来……   # 可选：一句情境
kind=repeat                # repeat 一条线 / groups 分组 / prefix 每组多取一种颜色
unit=RB                    # 重复单元（groups / prefix 里是"颜色循环 / 颜色顺序"）
shown=RBRBR?               # 题面：珠子紧挨着写，分组用 `/`，空位写 `?`
answer=B                   # 空位按顺序该是什么
rule=两颗一循环：红、蓝、红、蓝……
```

| 字段 | 说明 |
| --- | --- |
| `kind=repeat` | 一条直线上的循环，要 `unit` |
| `kind=groups` | 一组一种颜色、每组的颗数在变：`unit`（颜色循环）+ `counts=1,2,3,4` |
| `kind=prefix` | 每组把颜色顺序往后多取一种：`unit`（颜色顺序）+ `counts`（递增） |
| `fix=`（可选，跟 kind 无关） | 题面里有一颗放错了：`8:B>R`（第 8 颗该是红）/ `5:+R`（第 5 颗后面补一颗红，只用在分组题） |
| `story=`（可选） | 一句情境（假装是小汽车 / 小皮球 / 气球……），显示在题目名下面，也会被念出来 |

`?` 在直线题里就是"一颗空位"；在分组题里是"**一整组空着**"（该摆几颗，正是要孩子想的）。

## 接口（FastAPI）

单独跑在 **8040**；广场里挂在 `/api/games/pattern` 底下。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 活着没 |
| `GET` | `/api/levels` | 每档各几道 |
| `GET` | `/api/puzzles?level=1` | 列出某档的题 |
| `GET` | `/api/puzzles/{id}` | 按 id 取一道题 |
| `GET` | `/api/random?level=1` | 随机抽一道 |

返回给页面的是**已经解析好**的结构：`rows`（题面：珠子 / 空位 / 整组空着）、
`reveal_rows`（揭晓时：空位填上答案、放错的圈出来）、`answer_text`、`fix_text`、
`task`（那句任务说明）、`rule`（规律解释）—— 前端不用自己解析题目文件。

两道题都写 `history.record_served(...)`（跟别的游戏一样，历史页能看见）。

## 检查题库

```bash
python -m games.pattern.core.cards              # 全查一遍
python -m games.pattern.core.cards --list       # 顺手列出每档几道
python -m games.pattern.core.cards --show <题目文件>
```

盯的四件事：

1. 字段齐、`id` 跟文件名一致、`level` 跟所在目录一致；
2. **题面 + 答案跟写明的那条规律完全对得上**（拿 `unit` / `counts` 算一遍逐位比）——
   写错一颗都会被抓出来；
3. **答案唯一**：`repeat` 类整条序列的最短周期必须**正好**是 `len(unit)`
   （有更短的周期 = 还能用更简单的规律解释）；带 `fix` 的题把「只动一颗」的所有改法
   试一遍，**恰好一种结果**能修好（同一结果的不同说法算一种）；
4. **物理上限**：题面 + 答案里每种颜色不超过 10 颗（手上一共 60 颗）。
