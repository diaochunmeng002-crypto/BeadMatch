# logic —— 推理

**推理**（核心能力：条件约束）—— 从线索里推出答案：谁在第一个、谁在谁前面。

*Clues tell you where each bead goes. Line them up.*

## 现在有什么

| 文件 / 目录 | 说明 |
| --- | --- |
| `core/chinese.py` | 把题目原句翻成记号：`红色在最前面。` → `R@1` |
| `core/clues.py` | 线索记号：解析、判定、求解（6 颗珠子全枚举，毫秒级） |
| `core/puzzles.py` | 题目文件：读写、校验、扫题库、检查命令 |
| `api.py` | 后端接口（FastAPI）：参与者 + 题目 + 答案 |
| `web/` | 前端页面（原生 JS 三件套，不用构建） |
| `puzzles/<等级>/<id>.txt` | 题库（现在 1~6 级，每级 10 道，共 60 道） |

还没有 `game.toml` —— 所以广场首页暂时看不到它。

## 玩（前端）

```bash
python -m games.logic.api           # 默认 127.0.0.1:8010
```

打开 <http://127.0.0.1:8010> 就是页面（后端顺手托管了 `web/`，前端不用单独起）。

页面长这样：**参与者**（6 颗珠子）→ **题目**（你写的原句，一行一条）→ **排好的顺序**（6 个槽，从左到右）。

怎么玩：

- 点上面的珠子 → 放到最左边的空位；点槽里的珠子 → 拿回来
- **六颗摆满自动检查**：全对"叮"一声、槽位描绿边；有错"咚"一声，**没满足的那几条线索会标红**
- 「看答案」直接摆成答案（不会念出来）

朗读和键盘（跟串珠那套一个手感）：

| 操作 | 效果 |
| --- | --- |
| 点线索 | 选中并朗读这一条 |
| 点珠子 | 读颜色名（"红色"） |
| `空格` | 没选线索 = 读整道题；选了 = 重读那一条 |
| `↑` `↓` | 上一条 / 下一条线索，到头"咚"一声（`←` `→` 也一样） |

朗读会自动去掉 emoji（念出来是噪音）；音效是 Web Audio 合成的，不用素材文件。

## 接口（FastAPI）

```bash
python -m games.logic.api           # 默认 127.0.0.1:8010
```

然后 <http://127.0.0.1:8010/docs> 点着试。

| 接口 | 返回什么 |
| --- | --- |
| `GET /api/logic/health` | 活着没 + 题库目录 |
| `GET /api/logic/levels` | 每个等级各多少道题 |
| `GET /api/logic/puzzles?level=1` | 列出题目（只读文件头，比较快） |
| `GET /api/logic/puzzles/{id}` | **一道题：参与者 + 题目 + 答案** |
| `GET /api/logic/random?level=1` | 从某个等级里随机抽一道 |
| `POST /api/logic/check` | 交一个排法，看它对不对 |

取一道题返回的样子（**这就是"核心信息"**）：

```json
{
  "id": "20260915-213418-0857",
  "title": "彩虹排队",
  "level": 1,
  "participants": ["R", "B", "G", "Y", "P", "O"],
  "answer": ["R", "B", "G", "Y", "P", "O"],
  "clues": [
    {"text": "🔴 红色珠子排在最前面。", "notation": "R@1"},
    {"text": "🔵 蓝色珠子紧跟在红色后面。", "notation": "B>R"}
  ],
  "created_at": "2026-09-15 21:34:18",
  "created_by": "manual",
  "solution_by": "manual"
}
```

每条线索带**原文**（`text`，直接显示给孩子）和**记号**（`notation`，调试用）。
`title` 是**题目的名字**（可选）：有就显示，没有就是空字符串。

检查排法：

```
POST /api/logic/check
{"id": "20260915-213418-0857", "order": "R B G Y O P"}
```

```json
{"ok": false, "broken": [{"text": "🟠 橙色珠子排在最后面。", "notation": "O@6"}],
 "total_clues": 6, "order": ["R", "B", "G", "Y", "O", "P"]}
```

`order` 写字母或中文（`"红 蓝 绿 黄 橙 紫"`）都行。

## 题目格式

跟串珠一个路子：**注释区 + 元信息区 + 正文区**。正文区就是**题目本身 —— 一行一句，一字不改**。

```
# colors: Yellow Green Red Purple Blue Orange

created_at=2026-09-15 21:34:18
created_by=manual
solution_by=manual
id=20260915-213418-0857
title=彩虹排队
level=1
participants=R B G Y P O
answer=R B G Y P O

🔴 红色珠子排在最前面。
🔵 蓝色珠子紧跟在红色后面。
🟢 绿色珠子排在第三个。
🟡 黄色珠子在绿色后面。
🟣 紫色珠子在黄色后面。
🟠 橙色珠子排在最后面。
```

| 字段 | 例子 | 说明 |
| --- | --- | --- |
| `created_at` | `2026-09-15 21:34:18` | 什么时候生成的（**正文第一行**） |
| `created_by` | `manual` | 谁出的（**正文第二行**）：`manual` = 人给的题 |
| `solution_by` | `manual` | 这条解是谁给的（**正文第三行**） |
| `id` | `20260915-213418-0857` | 时间 + 随机后缀；文件名就是它，生成后不变 |
| `title` | `彩虹排队` | **题目的名字**（可选）：有就显示，没有就空着 |
| `level` | `1` | 难度等级（现在由出题人写） |
| `participants` | `R B G Y P O` | **参与珠子**：颜色首字母（也能写中文 `红 蓝 绿` 或 emoji `🔴`） |
| `answer` | `R B G Y P O` | **答案**：从左到右的顺序，写法跟 `participants` 一样 |

珠子一共这 6 个（写死）：`Y` 黄、`G` 绿、`R` 红、`P` 紫、`B` 蓝、`O` 橙。
汉字、字母、emoji 三种写法都认（`红` = `R` = `🔴`）。

**题目那几行是原句**，程序靠 `core/chinese.py` 看懂它；也接受记号写法（`R@1`），
两种混着写都行（所以以前写的题不用改）。读回再写出来是一字不差的。

## 线索记号

程序内部用这几个记号判定。位置从 **1** 起。

| 记号 | 读法 | 例子 |
| --- | --- | --- |
| `X@n` | X 在第 n 个 | `R@1` 红色在第一个；`P@6` 紫色在最后面 |
| `X>Y` | X 在 Y 后面 | `B>R` 蓝色在红色后面 |
| `X<Y` | X 在 Y 前面 | `P<R` 紫色在红色前面 |
| `X~Y` | X 和 Y 挨着（左右都算） | `G~B` 绿色和蓝色挨着 |
| `X!~Y` | X 和 Y 不挨着 | `G!~R` 绿色和红色不挨着 |
| `X~X` | **同色的两颗**挨着（L6 起用得上） | `P~P` 两颗紫色挨着 |

中文那边**不按句型硬套，而是抓关键信息**（规则在 `core/chinese.py`）：

| 句子里出现 | 意思 | 变成 |
| --- | --- | --- |
| 「最前面」 | 排第一 | `X@1` |
| 「第一个」「第三位」「第一支」 | 排第 N | `X@N` |
| 「最后」「最后面」「最后一个」 | 排最末 | `X@` 参与者的个数 |
| 「X 后面」 | 在 X 之后 | `X>Y` |
| 「X 前面」 | 在 X 之前 | `X<Y` |
| 「挨着」「不挨着」 | 相邻 / 不相邻 | `X~Y` / `X!~Y` |
| 「两颗 X 挨着」 | 同色的那两颗挨在一起 | `X~X` |

判断顺序是：**句子里第一颗提到的珠子是主语** → 看有没有"第几个/最后/最前" →
没有就看"谁在谁前面/后面"。所以「红色珠子排在最前面。」「红色第一个出发。」
「红色拿到了第一支冰淇淋。」都能读懂。

看不懂的句子会直接报错，并把原句和认出来的珠子一起打出来 —— 那时候把新说法告诉我，
我给 `core/chinese.py` 加一条。

## 怎么加题

1. 把题目（自然语言）给我 —— **原句直接进 txt，我不改你的话**；
2. 另外填 `participants`（参与者）和 `answer`（答案）；
3. 跑一遍检查，**必须每题都是「解=1」**。

## 检查题库

```bash
python -m games.logic.core.puzzles
```

每道题报一次「读得进来吗 / 解有几个 / 答案跟线索对不对」，最后报一次总数。

**只有"读不进来"算问题**（线索读不懂、id 跟文件名对不上这种）。另外两件事只提示一句，不拦：

| 提示 | 意思 |
| --- | --- |
| `解=N`（N > 1） | 线索不够，孩子排出别的答案也算对 —— 想唯一就再补线索 |
| `！你写的答案…不满足：…` | `answer` 那一栏跟线索对不上（游戏判定走线索，所以不影响玩；「看答案」会摆出你写的那个） |

打印一道题（顺便看程序有没有读懂）：

```bash
python -m games.logic.core.puzzles --show games/logic/puzzles/1/<id>.txt
```

输出里每条线索后面标着程序读到的记号：

```
# R@1   🔴 红色在最前面。
# B>R   🔵 蓝色在红色后面。
```

## 已经踩过的坑

**L6 起一颗珠子会重复。** 7 颗珠子但**只有 6 种颜色**，所以必有一色出现两颗。这种情况下：

- **位置类**线索照旧（"蓝色在第三个"= 第三个就是蓝的，不会歧义）；
- **关系类**线索按"**存在**"理解："红色在蓝色前面"= 有一颗红在蓝前面就行 ——
  因为两颗一模一样的珠子本来就分不出来；
- 写题时尽量别让"重复的那一色"当参照物（"黄在红前面"、红有两颗，孩子会懵），
  要么用位置线索点它，要么干脆不提它（让它靠排除法定位）。

**「紧跟」现在只按"在后面"处理。** "蓝色珠子紧跟在红色后面。"严格说是
「紧挨着 **且** 在后面」，程序现在按更宽松的 `B>R` 记（丢掉了"紧挨着"这点信息）。
现有 10 道 1 级题都验过是唯一解；万一以后哪道题因此变成多解，检查命令会直接报出来。

**线索里没提到的珠子会变成"多选题"。** 之前有一道题 6 句话里一次都没提橙色，
结果有 4 个答案（橙色放哪儿都行）。这类题必须补一条关于它的线索 ——
所以每道题都要过一遍「解=1」。

## 难度阶梯（各级实际用到什么）

> 完整的 L1~L20 规划（四个阶段、每级人数/重复色/考察重点）在
> [levels.md](levels.md) —— 这一节只记"已经做出来的那些级实际是什么样"。

| 等级 | 珠子 | 线索数 | 解 | 用到的线索类型 |
| --- | --- | --- | --- | --- |
| L1 | 6 | 6 | 1 | 绝对位置、谁在前/后 |
| L2 | 6 | 5~6 | 2~6 ⚠ | 绝对位置、谁在前/后、挨着 |
| L3 | 6 | 5~7 | 1 | 绝对位置、夹在中间、挨着、中间隔一个、谁在前/后 |
| L4 | 6 | 4~5 | 1 | 绝对位置、夹在中间、挨着、谁在前/后 |
| L5 | 6 | 5 | 1 | **中间隔一个**、谁在前/后（纯"距离"的一级） |
| L6 | **7** | 4~5 | 1 | 绝对位置、夹在中间、挨着（含"两颗同色挨着"）、中间隔一个、谁在前/后 |

设计新等级时注意：

- 只有"距离 + 方向"两种线索时，**最少要 5 条**才能唯一（L5 实测：4 条的所有组合都试过，没有唯一）；
- L2 那批是唯一一批没做到唯一解的（当初按"挨在一起"设计，没说左右顺序）。
