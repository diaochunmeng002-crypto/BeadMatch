# mathlab —— 数学实验室

**拿珠子做实验，把数学关系"摆"出来。**

它还是"**出题 → 孩子在实物珠子上操作 → 看答案/说明**"这个路数（跟另外六个游戏一样），
不一样的是**答案**：那边是"唯一的颜色序列 / 数字"，这边是**一条性质**
（"排成什么形状、拉开多远，总数都还是 3 颗"）。所以每道题除了 `answer`（性质），
还有 `example`（示例摆法）和 `why`（一句为什么）。

屏幕**不摆珠子**（珠子是实物）；**交互先不做** —— 页面只做三件事：出题、
把"怎么玩"说清楚（拿几颗、怎么摆、看什么）、给答案和示例。这是 2026-10-17 讨论定的方向。

```bash
python run.py                       # 广场首页第 7 张卡片（/games/mathlab/）
python -m games.mathlab.api         # 单跑这个模块（8050）
python -m games.mathlab.core.demos  # 列出演示 + 检查字段
```

接口路径跟别的游戏统一：演示在 URL 空间里也叫 `/api/puzzles`（`/levels`、`/random`、`/puzzles/{id}`），
这样广场的等级统计、历史页的「打开」、那几条公共测试都不用为它开特例。

## 一个演示长什么样

| 字段 | 是什么 |
| --- | --- |
| `thing` / `unit` | 这些珠子假装是什么（小球 / 气球 / 豆腐…）、量词（颗 / 个 / 块） |
| `theme` | 主题标签：数与量 / 加减 / 分组 / 乘除 / 分数 / 关系 / 图形空间 / 测量 / 数据 / 实验过程 |
| `materials` | **参与者**：拿几颗、什么颜色（`R:3`、`R:3 B:3`） |
| 正文 | **题目**：一行一步（1、2、3……最后一步就是那句"问"） |
| `answer` | 答案 = 一条性质（不是唯一结果） |
| `example` | 示例摆法：`标签\|珠子组\|说明\|标记`（珠子组用空格分开；标记只有 `wide`） |
| `why` | 一句"为什么"，给孩子听的那层解释 |

页面按这个结构自动画：**参与者**卡（一排珠子 + "红色小球 · 3 颗"）→ **题目**卡（编号步骤）→「看答案」→
答案卡（性质 + 示例摆法 + 为什么）。**没有自评按钮** —— 看完就是看完，换下一个演示或直接关掉（2026-10-17 反馈）。

右上角跟别的游戏一套：`难度`（`1 级（4 道）`……）、`读一遍`、`看答案`、`换一题`；
`←` `→` 换档。换一题是同档随机抽一个（现在这个会先剔掉，不会原地打转）。

## 怎么加一个演示

**一个演示一个文件**：新建 `puzzles/<等级>/<id>.txt`，照这个格式（注释区 + 元信息区 + 正文区）：

```
# colors: Yellow Green Red Purple Blue Orange

created_at=2026-10-17
created_by=manual
id=l2-split
level=2
title=数字拆拆乐
thing=糖球
unit=颗
theme=加减
materials=Y:4
example=4 拆成 2 和 2|YY YY|2 + 2 = 4|
answer=4 可以拆成 1 和 3、2 和 2 —— 不管怎么拆，合起来都还是 4。
why=分界线只是把同一排糖球切成两段；两段合起来，永远是原来那一排。

拿 4 颗黄糖球，摆成一排。
用一根筷子当分界线，把它分成两堆。
数一数两堆各有几颗。
挪一挪分界线：4 还能分成几和几？
```

`id` 用 `l<档>-<英文名>`，而且**必须跟文件名一致**；`level` 必须跟所在目录一致；
珠子用 `YGRPBO` 六色（黄绿红紫蓝橙）。前端不用改 —— 下拉框、题目卡、答案卡都按文件画。

`python -m games.mathlab.core.demos` 会把每个文件查一遍（字段、id/目录、颜色上限、示例标记）。

## 四档难度（概念递进，不对应年级）

| 档 | 名字 | 大概在做什么 |
| --- | --- | --- |
| L1 | 感知 | 观察和感受基本数学现象（数量守恒、一样多、哪边多） |
| L2 | 组合 | 数量的组成和简单操作（拆分、合并、平均分配） |
| L3 | 结构 | 乘法、分数、空间等结构关系（复制、方阵、等分） |
| L4 | 探索 | 小数量下的图形、测量、数据、关系和实验过程 |
