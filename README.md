# BeadMatch

实体玩具（木质底座 + 立柱 + 彩色木珠）的**出题工具**：
家长/老师用它生成一个初始局面，让小孩照着在实物上把珠子摆好，然后开始玩。

软件**不负责解题**——它只负责「出题」和「告诉人怎么摆」。

> 现在是「一个程序装多个游戏的**游戏广场**」：串珠 / 推理 / 记忆 / 计算。
> 一个游戏一个文件夹、自带题库和页面，广场只负责"有哪些游戏、怎么开"——见
> [docs/plaza.md](docs/plaza.md)。

## 现在能干什么

`python run.py` 起**广场**，首页 `/` 里挑游戏：

| 游戏 | 一句话 | 题量 |
| --- | --- | --- |
| **串珠**（规划） | 程序出一个局面，孩子照着在实物上把珠子摆好 | 300 道 |
| **推理** | 从线索里推出珠子的排列顺序（"小红在小绿前面"） | 70 道 |
| **记忆** | 看几秒 → 盖住 → 凭记忆把排列摆回来（**程序手里没有答案**） | 100 张 |
| **计算** | 用串珠数一数、比多少、做加减、分一分 | 120 张 |

每个游戏都带一个网页：按等级随机抽一道 → 画出来 / 念出来 → 孩子在实物上动手。
串珠另有**离线出题**：从已解局面按规则随机乱走 N 步 → **反走即解**（不需要求解器），
难度 = 解的长度 ÷ 10 向上取整（1~10 级各 20 道、11~20 级各 10 道）。

## 快速开始

```bash
python run.py        # 起广场
```

然后浏览器打开 <http://127.0.0.1:8000> —— 首页列出所有游戏，点进去就能玩。
其它命令（出题、跑测试、单独跑某一个游戏）见 [docs/how_to_start.md](docs/how_to_start.md)。

## 目录结构

```
BeadMatch/
├─ run.py               唯一入口：起广场（一个程序装所有游戏）
├─ plaza/               广场层：扫游戏、挂路由、托管首页和静态资源
├─ games/               游戏都在这儿，一个游戏一个文件夹
│  ├─ beadmatch/        串珠（规划）—— core + api + web + puzzles + tools + tests
│  ├─ logic/            推理
│  ├─ memory/           记忆
│  ├─ calc/             计算
│  └─ pattern/          找规律（占位 README，还没做）
├─ start/               怎么跑、怎么发：桌面启动器 / 打包脚本 / 图标
└─ docs/                广场规划 / 需求 / 启动命令 / 讨论流水 / 调研
```

每个游戏都长一个样：`core/`（纯逻辑）+ `api.py`（接口，导出一个 `router`）+
`web/`（原生 JS 三件套，不用构建）+ `puzzles/`（题库）+ `README.md`，外加一个
`game.toml`（广场靠它发现游戏）。想加第五个游戏，丢一个这样的文件夹进去就行。

## 只有一套规则

一次挪一颗，**落点只要有空位就能放**（不要求同色）。细节见 [docs/requirement.md](docs/requirement.md) §2。

> 的规则），当时用来算难度/找短解，现在**已删除**——原因和经过见
> [docs/requirement.md](docs/requirement.md) §8.2 与 [docs/solver_research.md](docs/solver_research.md)。
